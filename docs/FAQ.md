# GitHub Risers: FAQ

## What is GitHub Risers?
A leaderboard of GitHub repositories ranked by how fast they gain stars, not by how many they already have. AI is the main board; Developer Tools, Security, Web / Frontend, Infrastructure, Design / Creative and Data have their own boards. It is generated by scripts from the GitHub API and updated twice a day.

## How is it different from sorting by total stars?
Total-star lists keep the oldest giants on top. GitHub Risers divides stars gained in a window (7, 30 or 365 days) by the number of days, so a project that is taking off now can outrank one that is merely famous. Total stars still appear, as the last board in each category.

## Is it the same as GitHub Trending?
No. GitHub Trending is GitHub's own page. GitHub Risers is an independent, open-source project with published rules, five languages and a saved history of every update. It is not affiliated with GitHub.

## How is the growth rate computed?
`per_day = stars gained over the window / days used`. The gain is the sum of daily star counts from `GET /repos/{owner}/{repo}/stargazers/history` over the complete UTC days before the run. A repository younger than the window is divided by its own age and marked "young". See [FACTS.md](FACTS.md).

## How often is it updated?
Twice a day, at 00:00 Beijing time (UTC+8) and 00:00 Los Angeles time. The schedule runs on GitHub Actions cron, so a run can start a few minutes late. Each run is archived in its own folder under `rankings/`.

## Where do the numbers come from? Are any estimated?
Only the GitHub API. A project that cannot be fetched is shown as missing data; numbers are never typed in or estimated.

## How are repositories assigned to a category?
Tracked projects (`data/projects.json`) each have one category. Newcomers are found by GitHub topic: a repo must carry one of the category's own topics. Owners tag their repos, so an occasional off-topic hit is possible. Rules: [CATEGORIES.md](CATEGORIES.md).

## What is "Hottest new repos"?
Repositories created in the last 7 days with at least 100 stars, excluding forks and archived repos, ranked by stars divided by age in days. See [NEW_ARRIVALS.md](NEW_ARRIVALS.md).

## Does it detect fake stars?
No. It reports the counts GitHub returns. It only flags, with a published heuristic, new repos that look like cracked, pirated or activator bundles, and ranks them after all normal repos without hiding them.

## Does it use generative AI?
The rankings are computed by plain scripts. Descriptions of new repos can be translated and polished with an AI model in an optional CI step; numbers are never produced that way.

## Is it affiliated with GitHub?
No. "GitHub" is used only to say whose data it ranks.

## Does the site track visitors?
No. There are no analytics, tracking or beacon scripts anywhere in the repo.

## How do I cite it?
Use [CITATION.cff](../CITATION.cff) (GitHub shows a "Cite this repository" button), and mention the date of the snapshot you used, for example `rankings/2026-10-30/cn-0000/`.

## How can I suggest a project or report a mistake?
Open an issue, or send a pull request that edits `data/projects.json` or `data/categories.json` (all five languages required). Generated files (`README*.md`, `data/stats.json`, `latest/`, `rankings/`) are never edited by hand. See [CONTRIBUTING.md](../CONTRIBUTING.md).
