# Contributing to GitHub Risers

Thanks for helping. Short version: change the **inputs**, never the generated outputs, and open a pull request.

## What you can change
- `data/projects.json`: tracked projects. Each entry needs one valid `category` and a `desc` in all five languages: `en`, `zh-Hans`, `zh-Hant`, `ja`, `ko`.
- `data/categories.json`: category names, descriptions and topics (also five languages).
- `data/newcomer_i18n.json`: hand-written translations of new-repo descriptions.
- `docs/`: documentation and the GitHub Pages site.

## What you must not edit by hand
`README*.md`, `data/stats.json`, `latest/`, `rankings/` are generated by `tools/update_stars.py` and `tools/render_readme.py`. History snapshots under `rankings/` are append-only.

## Rules of the project
- Star numbers come from the GitHub API only. Never type or estimate numbers; mark missing data as missing.
- Zero telemetry: no analytics, tracking or beacon scripts.
- No star buying, swaps or manipulation. Suggestions that ask for any of that are closed.
- Changes go through pull requests; do not push to `main`.

## Check before you push
```sh
python3 tools/verify.py
```
This compiles the tools, runs the tests and checks that the generated READMEs are current. It needs no network. CI runs the same command.

## Suggesting a project
Open an issue with the repository link, the category you think fits and why. Tracked projects are chosen to cover each category; the "Hottest new repos" boards are found automatically by topic.
